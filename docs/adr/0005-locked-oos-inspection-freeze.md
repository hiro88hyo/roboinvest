# ADR-0005: Locked OOS Inspection Freeze

Date: 2026-07-04

Status: Accepted

## Context

ADR-0004 introduced locked OOS as the last research check after train,
validation, purge windows, matched random baselines, and pre-registration.
The event swing cycle has now inspected the same locked OOS window for
multiple rule-only candidates. That does not invalidate the reports, but it
does mean surviving candidates must be treated as survivors of a multi-look
research process rather than a clean one-shot OOS discovery.

This ADR records the inspection history and freezes the current locked OOS
window for this research cycle.

## Decision

The current locked OOS window is frozen for this event swing research cycle.
New locked OOS inspection is allowed only when one of the following is true:

1. At least 60 new trading days of forward data have accumulated after the
   current locked OOS end.
2. The user gives explicit approval for a named inspection before it is run.

No implementation task in the current swing improvement cycle requires another
`--split locked-oos --include-locked-oos` run. Existing locked OOS results may
be cited as already-known context, but they must not be mined for new threshold,
exit horizon, stop, PER, dividend yield, technical veto, or selection-order
changes.

The next true OOS evidence for live eligibility will come from 2026-07 onward
forward data and paper observation. Paper observation can collect operational
evidence without capital risk, but it is not a live promotion and does not
weaken ADR-0004 or the project kill switch in `AGENTS.md`.

## Consequences

- Cluster v1 must be described as a survivor of a multi-look cycle, not as a
  clean one-shot locked OOS winner.
- Rejected candidates remain rejected unless a new train-only hypothesis is
  pre-registered before any further validation or OOS inspection.
- Train-only scanners and reports may mark families in this registry as
  already inspected so future hypothesis selection does not unknowingly recycle
  a viewed family.
- Past-direction data expansion must not move validation or locked OOS
  boundaries for promotion decisions; use a fixed split manifest when adding
  older J-Quants history.
