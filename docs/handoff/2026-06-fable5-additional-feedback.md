# roboinvest 反・酷評レビュー — 「設計通り完璧に動いている。目的関数が儲けではないだけ」

> 前提: 定型的な酷評(オーバーエンジニアリング→アルファ不在→計測なし→LLM誤用)は開発者に「予想通り」と消化済み。
> 本レビューは採点基準そのものを変える。建設的・批判的、かつ予測不能であることを目的とする。
> 作成日: 2026-06-12 / 関連: (2026-06-fable5-feedback.md（前回の定型酷評+改善プロンプトセット)

## テーゼ1: アルファが無いことは、このリポジトリについて最も重要でない事実である

開発者は「RSI閾値にアルファはない」ことを最初から知っている。contracts/によるSSOT、per-service CLAUDE.md、handoff文書の精度を見れば、教科書3ページ目の指標で市場に勝てると信じる知的水準でないことは明白。戦略はプレースホルダとして意図的に弱い。

刺さるべき批判は「戦略が弱い」ではなく、**「プレースホルダのまま本番資金が投入された」**こと。

## テーゼ2: 真の目的関数は「プロジェクトの存続」— 顕示選好が証明している

ソロ開発者の優先順位付けは顕示選好(revealed preference)である。

| 完成したもの | 先送りされたもの |
|---|---|
| OTel Collector | PnL計測(0行) |
| Cloud Logging構造化 | パラメータスイープ(不在) |
| Dashboard Realtime購読 | バックテストレポート(1枚もない) |
| 9サービスのCI/CD・dependabot | アラート(「次セッション」) |
| paper/live分離・型生成パイプライン | 戦略の有効性検証(一度もない) |

パターン: **完成した項目はすべて「次に作るものを生む」。先送りされた項目はすべて「プロジェクトに判決を下す」。**

計測を実装すれば数週間以内に「期待値マイナス」の判決が出て、作る理由が消える。計測の不在は手抜かりではなく、プロジェクトの生存本能である。

資金を守るキルスイッチは3層(日次・週次・月次)あるのに、**プロジェクト自身を止めるキルスイッチは1つもない**。守られているのは100万円で、最も高価な資産(開発者の数百時間)は無防備。

## テーゼ3: 算数 — 全批判を解消しても「ドチャクソ」は数学的に不可能

- 資金100万円 × 2%ルール = 1トレードのリスク2万円
- 例外的に優秀なシステム(年率50〜100%、Sharpe 2級)が完成しても年間利益は**50〜100万円**
- 投入済み開発時間は538ファイル・handoffログの期間から数百時間規模 = エンジニア時間単価換算で**数百万円を投資済み**

最良シナリオでも回収に数年。儲けの方程式(エッジ×回転×サイズ−コスト)のうち、このプロジェクトが永久に固定しているのは「サイズ」であり、サイズが小さい限りエッジの完成は損益にほぼ寄与しない。

前回の改善プロンプトセット(CHK-01〜10)は**間違った乗り物のエンジンを精密に整備する手順書**だった(前回レビューの自己批判として明記)。

個人アルゴで大きく儲けた実例の経路は例外なく「①検証済みトラックレコード→②資本のスケール」であり、「③100万円のまま戦略を磨き続ける」ではない。そして①に必要な計測を、このプロジェクトは構造的に避けている(テーゼ2)。ループは閉じている。

## テーゼ4: 本当に一級品なのは、誰も褒めなかった場所にある

1. **AI協働開発の方法論として商用水準超え**: スキーマ駆動contracts、per-service CLAUDE.md、handoffによる文脈の世代間継承、phase管理。2026年時点でほとんどのプロ開発チームができていないことを個人が実装している。「Claude Codeで複数サービスを統治するリファレンスアーキテクチャ」として公開価値がある
2. **運用規律が個人として異常に高い**: インシデント当日文書化(6/8 closeout guard欠陥)、自発的リスクオフpaper日、reconcile/preopen check整備。負けた日の行動の質は能力の最も信頼できる証拠
3. **小型株tick+板アーカイブ**: 商用で買えないデータが毎営業日蓄積される、唯一価値が複利で増える構成要素

開発者の実像は「2流のポートフォリオマネージャー」ではなく、**「1流のプラットフォームエンジニア兼オペレーターが、自分の最弱スキル(銘柄選択)で勝負する競技を自ら選んでいる」**。批判すべきは能力ではなく競技選択。

## テーゼ5: +46,766円は、起こりうる中で最悪の結果だった

大きく負けていれば検証フェーズに強制送還された。ゼロなら見直しが入った。「AI戦略が完全沈黙したまま、検証ゼロのルールで小幅プラス」は**間欠強化**として継続を最も強く動機づける — カジノが客に序盤に勝たせるのと同じ報酬構造を、システムが開発者自身に与えた。-45,540円の日ですら「振り返り文書を書く楽しさ」に変換されている。

## 処方箋: システムのリスク管理思想を、プロジェクト自身に適用せよ

コードを1行も書かずに済む提案。GatewayがCLAUDE.mdのビジネスルールを強制執行するのと同じ形式で、**プロジェクトの反証契約(pre-registration)をCLAUDE.mdに追記する**:

```markdown
## プロジェクト・キルスイッチ(資金ではなくプロジェクトに適用)

- 期限: 2026-09-30
- 判定条件: アウトオブサンプル期間でPF > 1.2 かつ 最大DD < 資金の10% を、
  事前登録したパラメータ(変更不可)で達成すること
- 条件未達の場合: 戦略開発を停止し、本リポジトリの資産を以下に転用する
  1. AI協働開発リファレンスとしての公開・記事化
  2. 板アーカイブの研究データセット化
  3. トレード再開は「資本スケールの計画」を先に文書化した場合のみ
- このルールの変更には、変更理由の文書化と1週間の冷却期間を要する
```

ポイントは判定基準を**計測する前に**書いて固定すること。シャープレシオの実装は誰でもできる(それも「作る楽しさ」の供給にすぎない)。**どの数字が出たらやめるかを先に署名すること**だけが、このプロジェクトが自分に課したことのない種類の痛みである。

## 締め

「予想通りの反応でした」と言えること自体が診断結果である。批判を予測できて行動が変わっていないなら、批判はプロジェクトの入力ではなく**観賞物の一部**になっている。

本レビューの中核は感想ではなく算数 — **資金100万円である限り、全批判を解消した完璧なシステムでも「ドチャクソ」には到達しない**。「予想通り」と受け流すには計算への反論が必要で、反論できないなら選択肢は三つ:

1. 資本をスケールする計画を立てる
2. 目的関数を正直に書き換える(趣味と認めて存分に楽しむ — 正当な選択である)
3. 反証契約に署名する

現状維持だけが、選択肢に含まれていない。
